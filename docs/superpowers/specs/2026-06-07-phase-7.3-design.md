# Phase 7.3: From "Clickable" to "Playable"

Date: 2026-06-07

## Goal

Player can understand the game state and play 3 minutes continuously without debug overlay. The game transitions from "3D scene with debug" to "a playable card table."

**Acceptance criteria:**
- Player sees 13 hand tiles on start
- Status banner shows whose turn it is
- Clicking draw/discard works and is visually confirmed
- Discard panel shows the last played tile
- Discard area accumulates each player's discards
- AI acts automatically with visible feedback
- ActionBar buttons match current legal actions
- Mobile portrait layout is stable at 480px max-width
- 20 continuous actions without deadlock

## 1. Fix advancedTile Lifecycle

### Problem

Three contradictions exist:
- `legalActions` in store: when `hasAdvancedTile`, only PEEK/PUT_TILE_IN_HAND allowed (correct)
- `game-state-manager.ts:100-109`: `discardTile()` allows consuming `advancedTile` directly (wrong)
- `playable-flow.test.ts:167-183`: test validates direct discard of advancedTile (wrong)

### Resolution

**Rule**: `advancedTile` is a temporary held tile. It must be PUT_TILE_IN_HAND before any DISCARD_TILE is allowed.

### Changes

**`packages/web-core/src/server/game-state-manager.ts`**
- Remove lines 100-109 (the `advancedTile` branch in `discardTile()`)
- `discardTile()` should only search `handTiles`

**`packages/web-core/src/server/local-mock-server.ts`**
- In `handleDiscardTile()`, add guard: if `player.advancedTile !== null`, return early

**`apps/web/src/stores/game.ts` — legalActions computed**
- Current code (line 88-90): `hasAdvancedTile` → `[PEEK_ADVANCED_TILE, PUT_TILE_IN_HAND]`
- Fix: distinguish peeked state:
  - `hasAdvancedTile && !hasPeeked` → `[PEEK_ADVANCED_TILE, PUT_TILE_IN_HAND]`
  - `hasAdvancedTile && hasPeeked` → `[PUT_TILE_IN_HAND]`
- Need computed: `hasPeekedAdvanced = computed(() => myPlayer.value?.hasPeekedAdvanced ?? false)`

**`packages/web-core/src/server/__tests__/playable-flow.test.ts`**
- DELETE test: "should allow discarding advanced tile directly" (lines 167-183)
- ADD test: "should reject discard when advancedTile exists"
- ADD test: "should allow discard after PUT_TILE_IN_HAND"
- ADD test: "peek deducts -2 behavior score"
- ADD test: "no-peek does not deduct behavior score"

## 2. New Components

All components are DOM overlays, reading from the existing Pinia `useGameStore`.

### 2.1 GameStatusBanner.vue

**File**: `apps/web/src/components/GameStatusBanner.vue`

Replaces the existing `status-bar` div in GameView. Shows a single, large, centered status message.

**Status text logic** (computed from store):
| Condition | Text |
|-----------|------|
| `!connected` | "点击开始游戏" |
| `isGameOver && isMyWin` | "恭喜你赢了！" |
| `isGameOver` | "游戏结束" |
| `isWaitingForBot` | "等待 {botName} 出牌..." |
| `isMyTurn && stage === 'beforeDraw'` | "轮到你：请选择摸牌方式" |
| `isMyTurn && hasAdvancedTile && !hasPeeked` | "你提前拿了一张牌：选择看牌或放入手牌" |
| `isMyTurn && hasAdvancedTile && hasPeeked` | "你已看牌：放入手牌后出牌" |
| `isMyTurn && stage === 'inHand' && selectedTile` | "已选牌：点击「出牌」确认" |
| `isMyTurn && stage === 'inHand'` | "你已摸牌：请选择一张牌打出" |
| `stage === 'discarded' && canPong` | "你可以碰：{tileName}" |
| Otherwise | "等待对手..." |

**Props**: None (reads store directly)

**Style**: Large text, dark semi-transparent background, centered, rounded.

### 2.2 CurrentDiscardPanel.vue

**File**: `apps/web/src/components/CurrentDiscardPanel.vue`

Shows the most recently discarded tile in a large, prominent format.

**Behavior**:
- Watches `gameState.lastDiscardedTile` and `lastDiscardedBy`
- When a new discard appears, shows for 1.5s at full size, then shrinks
- Shows player name + tile in large format

**Display**:
```
{playerName} 打出
[ tile value + suit ]
```

**Position**: Center of screen, above hand layer. DOM overlay with transition animation.

### 2.3 DiscardAreaLayer.vue

**File**: `apps/web/src/components/DiscardAreaLayer.vue`

Shows each player's accumulated discards (most recent 6).

**Layout**:
- Self (seat 0): bottom-left, above hand tiles
- Bot 1 (seat 1): top-left
- Bot 2 (seat 2): top-right

**Content per player**: Small tile cards showing value + suit. Most recent first.

**Data source**: `gameState.players[i].discardedTiles.slice(-6)`

### 2.4 SeatHudLayer.vue

**File**: `apps/web/src/components/SeatHudLayer.vue`

Shows player info for all 3 seats.

**Per seat display**:
- Player name
- Hand tile count (actual for self, `13` or `14` for others based on turn)
- Behavior score
- Turn indicator (glow/highlight when `currentTurnSeatId === seatId`)
- Bot thinking indicator when bot is acting

**Layout**:
- Seat 0 (self): bottom-left corner
- Seat 1 (bot): top-left
- Seat 2 (bot): top-right

### 2.5 ActionBar.vue

**File**: `apps/web/src/components/ActionBar.vue`

Replaces the inline action buttons in GameView. All buttons derived from `legalActions`.

**Button states by stage** (derived from `legalActions` computed):

| Stage | legalActions | Buttons |
|-------|-------------|---------|
| `beforeDraw` (my turn) | DRAW_TILE, DRAW_TILE_ADVANCED, SHOW_HAND | 摸牌, 提前拿牌, 亮牌 |
| `hasAdvancedTile && !hasPeeked` | PEEK_ADVANCED_TILE, PUT_TILE_IN_HAND | 看牌 (-2), 不看·放入手牌 |
| `hasAdvancedTile && hasPeeked` | PUT_TILE_IN_HAND | 放入手牌 |
| `inHand` (my turn) | DISCARD_TILE, SHOW_HAND | 出牌 (disabled if no selection), 亮牌 |
| `discarded` (canPong) | CLAIM_PONG, PASS | 碰, 过 |
| `discarded` (canKong) | CLAIM_KONG, PASS | 杠, 过 |
| `discarded` (canWin) | CLAIM_WIN, PASS | 胡, 过 |
| `waitingBot` | [] | "等待电脑出牌..." (text only, no buttons) |
| `isGameOver` | — | 再来一局 |

**Note**: The store's `legalActions` computed must be updated to distinguish peeked vs not-peeked advancedTile states. Currently it only checks `hasAdvancedTile` without differentiating peek state.

**Style**: Horizontal button row, primary/secondary/accent colors matching existing scheme.

## 5. Acceptance Mode

**Trigger**: URL parameter `?mode=acceptance` (read via `new URLSearchParams(window.location.search)` in main.ts or App.vue)

**Behavior**:
- Fixed random seed for `shuffleTiles` (seed = 42) — pass seed to shuffle function
- Fixed bot behavior: always discard leftmost tile (index 0)
- Disable random leak: `checkLeak` always returns `{ leaked: false }`
- Disable random favor: `isFavored` always returns `false`
- Disable random bot timing: fixed 800ms delay (no `Math.random()` component)

**Implementation**:
- Add `acceptanceMode: boolean` option to `LocalMockServer` constructor
- Read URL param in `apps/web/src/main.ts` or the transport factory in store
- Pass `acceptanceMode` through to `LocalMockServer`
- `LocalMockServer` passes it to `shuffleTiles` (seed param) and bot logic
- In acceptance mode, `shuffleTiles` uses a seeded PRNG instead of `Math.random()`
